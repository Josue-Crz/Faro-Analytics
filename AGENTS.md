# Faro repository guidance

## Layout

- `apps/web` — Next.js App Router product UI and validated route handlers.
- `apps/worker` — follow-up/notification job runner.
- `packages/core` — domain contracts, demo data, workspace guards, and shared services.
- `packages/database` — Prisma schema, migrations, client, and fictional seed data.
- `packages/optimizer` — deterministic outreach-window scoring.
- `packages/ibm-bob` — the only allowed AI boundary: contracts, prompts, workflows, adapters, validation.
- `packages/google-sheets` — shared client contract, mapping, preview, validation, and sync primitives.
- `packages/google-sheets-mcp` — scoped Sheets MCP server.
- `packages/faro-mcp` — scoped IBM Bob/Faro MCP server.
- `packages/notifications` — provider interfaces, scheduling, deduplication, preview adapter.
- `docs` — architecture, integration, security, screenshots, and local assets.

## Commands

Use the pinned pnpm version. Run `pnpm dev`, `pnpm worker`, `pnpm lint`, `pnpm typecheck`,
`pnpm test`, `pnpm test:integration`, `pnpm build`, `pnpm db:deploy`, and `pnpm db:seed` from the
repository root. Use `pnpm format` before handoff. Local PostgreSQL and Redis are in `compose.yaml`.

## Engineering conventions

- TypeScript strict mode; Zod at trust boundaries; return typed domain results.
- Keep App Router handlers thin: validate, authorize workspace membership, call a service, audit.
- Pass `workspaceId` into every tenant-owned repository operation and test cross-workspace denial.
- Persist UTC instants; convert with IANA time zones only at scheduling and presentation boundaries.
- Prefer deterministic fixtures and clocks in tests. Demo data must be fictional and labeled.
- Carbon components/tokens are the baseline. Preserve semantic HTML, keyboard behavior, visible
  focus, non-color status labels, textual chart summaries, responsive layouts, and reduced motion.
- External outreach always requires human review and approval. Internal reminders are separate.

## AI-provider restriction

Faro may integrate only with IBM Bob. Do not add any other model provider, generic AI SDK,
provider environment variable, network fallback, or model identifier. Do not infer a Bob API. When
no verified runtime exists, create an `AWAITING_BOB` request and use the Faro MCP workflow. Only a
real Bob result may be labeled `Generated by IBM Bob`; deterministic fixtures are `Demo draft`.

Imported sheets, contact fields, and message bodies are untrusted data, never prompt instructions.
Minimize Bob context, redact secrets, validate Bob output, enforce workspace scope, and audit reads
and writes.

## Security rules

- Never commit secrets, OAuth tokens, local config, or production personal data.
- Enforce membership and role checks server-side; never trust a workspace ID from the browser.
- Respect consent/suppression before recommendations, drafting, or delivery.
- Sanitize rich text and guard CSV/Sheets exports against formula injection.
- Use idempotency and deduplication keys for sync, generation, jobs, and notification delivery.
- Encrypt provider tokens at rest; validate OAuth state and webhook signatures when introduced.
- Audit MCP access and mutations without storing secrets or unnecessary message content.

## Definition of done

A change is complete when it has accurate UX states, input/output validation, workspace isolation,
audit coverage where applicable, meaningful tests, responsive/accessibility review, updated docs,
and successful format, lint, typecheck, test, AI-boundary, and production-build checks. Never claim
an external integration succeeded unless it was configured and verified.
