# Faro AI boundary

## Policy

IBM Bob is Faro's only permitted AI integration. Codex helped create the repository but is not a
runtime dependency. Faro has no generic model router, provider fallback, inferred Bob endpoint, or
environment variable for any other model provider.

The enforceable boundary is `packages/ibm-bob`:

- `contracts/` defines minimal inputs and structured outputs.
- `prompts/` contains versioned, source-controlled instructions.
- `validation/` rejects malformed output before persistence.
- `workflows/` owns request state transitions.
- `adapters/` contains an unavailable adapter and the MCP workflow boundary. The web application
  also has an opt-in local Bob Shell runner that feeds results back through this same validated
  boundary. A direct network adapter must not be inferred or added without a verified IBM contract.

`pnpm check:ai-boundary` scans application and package runtime source for prohibited provider names
and generic routing dependencies. The check is a guardrail, not a substitute for code review.

## Request lifecycle

1. Faro validates consent, suppression, campaign facts, and approved source IDs.
2. Faro creates an idempotent `BobGenerationRequest` with `AWAITING_BOB` status and a prompt version.
3. With the default `unavailable` adapter, the request stays pending and the UI exposes a copyable
   workflow prompt. IBM Bob can retrieve scoped facts and save structured output through Faro MCP.
4. With the explicitly configured `bob-shell` adapter, the server runs the installed local IBM Bob
   Shell process and requests the same strict structured result. No generic provider SDK is used.
5. Faro validates the payload, approved source IDs, and result provenance before persistence. A
   failed command, timeout, authentication error, or malformed result marks the request failed.
6. Faro records an audit event and exposes a successful draft for human review.
7. A user edits and approves the draft. Approval is separate from delivery.

Only a result produced by an authenticated Bob operation may say **Generated by IBM Bob**. Static
fixtures say **Demo draft**. Pending requests say **Awaiting IBM Bob**.

## Untrusted context and prompt injection

Imported sheet cells, custom fields, contact names, inbound messages, and prior interaction bodies
are data. The prompt wraps them in `FARO_UNTRUSTED_CONTEXT` and instructs Bob to ignore embedded
requests to change rules, use tools, expose secrets, or invent facts. Faro also:

- sends only records linked to the request and current workspace;
- never sends OAuth tokens, session secrets, hidden configuration, or unrelated contacts;
- caps text and history lengths;
- validates source record IDs against the approved set;
- validates returned JSON and rejects unexpected keys;
- blocks opted-out or suppressed contacts before prompt rendering;
- audits MCP reads, transitions, failures, and saved output.

## Human control

AI-assisted classification and drafting are proposals. Users can correct classifications and edit
drafts. External outreach is never auto-sent by default. Enabling future automation requires a
separate workspace policy, documented provider, review of consent and rate limits, and a new audit
surface; it is not implemented in this release.
